# payment 模块技术设计

## 1. 概述

- 沿用 Spring Boot 3.2 + MyBatis-Plus 3.5.7，复用 `common`。
- 引入 OpenFeign：`payment` 调用 `order` 的「标记已支付」接口。
- 分层：`controller → service → mapper → entity/dto`，跨服务调用收敛在 `client`。

## 2. 跨服务依赖

### 2.1 依赖 order 的接口

| 接口 | 用途 | 现状 |
|---|---|---|
| GET /order/internal/order-no/{orderNo} | 创建支付单时校验订单归属、状态与金额 | **需补充** |
| POST /order/internal/order-no/{orderNo}/mark-paid | 支付成功后把订单推进到已支付 | **需补充** |

> 这两个内部接口是 payment 的前置依赖，开发时在 order 补齐，并把 `OrderStatus` 扩展出 `PAID(20)`。内部接口仅服务间 Feign 直连使用，不加入网关白名单。

### 2.2 状态流转约定

订单状态：

```text
10 待支付 ──支付成功──▶ 20 已支付
10 待支付 ──取消────▶ 50 已取消
```

支付单状态：

```text
10 待支付 ──回调成功──▶ 20 已支付
```

## 3. 表结构

### 3.1 支付单表 t_payment

```sql
CREATE TABLE IF NOT EXISTS t_payment (
    id BIGINT NOT NULL COMMENT '主键(雪花ID)',
    payment_no VARCHAR(64) NOT NULL COMMENT '支付单号',
    order_no VARCHAR(64) NOT NULL COMMENT '订单号',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    amount INT NOT NULL COMMENT '支付金额(分)',
    channel VARCHAR(32) NOT NULL DEFAULT 'mock' COMMENT '支付渠道',
    status TINYINT NOT NULL DEFAULT 10 COMMENT '10待支付 20已支付',
    paid_at DATETIME DEFAULT NULL COMMENT '支付时间',
    deleted TINYINT NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_payment_no (payment_no),
    UNIQUE KEY uk_payment_order (order_no),
    KEY idx_payment_user (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='支付单表';
```

> `uk_payment_order` 用订单号做唯一索引，天然实现「一单对应一个支付单」的创建幂等。


## 5. 支付时序

```text
前端 → payment
  1. 创建支付单：校验订单 → 幂等创建
  2. 发起支付（mock）：直接返回支付成功
  3. 支付回调：幂等校验 → 更新支付单为已支付
     → 通知 order 标记已支付（失败重试）
```

## 6. 幂等与一致性

- 创建支付单幂等：`order_no` 唯一索引，重复创建捕获唯一键冲突后返回原支付单。
- 回调幂等：支付单已「已支付」则直接返回成功，不重复通知。
- 最终一致：先本地更新支付单，再 Feign 通知 order；order 通知失败时，因回调本身可安全重试，由重试兜底。

## 7. 错误码扩展

| 错误码 | 含义 |
|---|---|
| 400 | 参数错误 |
| 403 | 无权操作该支付单 |
| 404 | 支付单不存在 / 订单不存在 |
| 409 | 订单状态不允许支付 / 重复创建 |

## 8. 校验与安全

- 金额以服务端订单金额为准，不信任前端传值。
- 支付单按 `X-User-Id` 隔离，归属校验在 Service 层完成。
