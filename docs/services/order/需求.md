# order 模块需求文档

## 1. 背景与目标

`order` 是交易链路的中心。本期目标：打通「下单 → 扣库存 → 生成订单 → 取消回补」这一核心闭环，为后续 `payment` 支付模块提供订单基础。

## 2. 用户与场景

- 已登录用户：提交订单、查看自己的订单列表与详情、取消订单。
- 下单是跨服务动作：`order` 需调用 `product` 扣减库存、快照 `user` 的收货地址。

## 3. 功能范围

### 本期 P0

| 编号 | 功能 | 说明 |
|---|---|---|
| O-01 | 提交订单 | 指定 SKU、数量、收货地址，扣库存并生成订单 |
| O-02 | 订单列表 | 按状态分页查询本人订单 |
| O-03 | 订单详情 | 查看订单与明细 |
| O-04 | 取消订单 | 待支付订单可取消，取消回补库存 |

### 后续（不在本期）

- 购物车、多商品合并下单、支付回调、优惠券/促销、退款、发货。

## 4. 功能详述

### O-01 提交订单

- 入参：`skuId`、`quantity`、`addressId`、可选 `remark`。
- 流程：校验 SKU 与库存 → 扣减库存 → 创建订单与明细 → 返回订单号。
- 金额：订单总价 = SKU 单价（分） × 数量，由下单时的 SKU 价格快照计算。
- 幂等：同一客户端请求重复提交不重复扣库存、不重复建单。

### O-02 / O-03 订单查询

- 列表按 `user_id` 隔离，支持按状态过滤，按创建时间倒序。
- 详情返回订单基本信息 + 明细列表 + 收货地址快照。

### O-04 取消订单

- 仅「待支付」状态可取消。
- 取消成功后回补库存。
- 取消是最终状态，不可逆。

## 5. 非功能需求

- 幂等：下单防重复提交。
- 一致性：扣库存与建单跨服务，用「先扣减、失败回补」保证最终一致。
- 安全：订单按 `X-User-Id` 隔离，越权访问返回 403。

## 6. 验收标准

- 能成功提交订单，库存相应减少，订单与明细正确落库。
- 重复提交同一请求不产生重复订单、不重复扣库存。
- 用户只能看到并操作自己的订单。
- 取消待支付订单后，库存回补，订单状态变为已取消。
