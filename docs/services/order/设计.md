# order 模块技术设计

## 1. 概述

- 沿用 Spring Boot 3.2 + MyBatis-Plus 3.5.7，复用 `common`。
- 新增 Spring Cloud OpenFeign：`order` 调用 `product` 的库存接口。
- 分层：`controller → service → mapper → entity/dto`，跨服务调用收敛在 `client`（Feign）包。

## 2. 跨服务依赖

### 2.1 依赖 product 的接口

| 接口 | 用途 | 现状 |
|---|---|---|
| POST /product/stock/deduct | 原子扣减库存 | 已有 |
| POST /product/stock/restore | 取消/失败时回补库存 | **需补充** |

> `restore` 为 order 的前置依赖，开发时在 product 补齐：`UPDATE t_product_sku SET stock = stock + ? WHERE id = ?`。

### 2.2 依赖 user 的地址

下单入参只传 `addressId`，order 侧**不做实时 Feign 查询**，而是由前端在提交订单前把地址信息一并传给 order，order 存为快照。这样下单链路不额外依赖 user 的实时可用性。

### 2.3 已知约束

`product` 商品更新目前是「删除旧 SKU 重建」，会重置 SKU id 与库存。P0 期间下单依赖 SKU 稳定存在即可，SKU 重建策略的改造放后续。

## 3. 表结构

### 3.1 订单表 t_order

```sql
CREATE TABLE IF NOT EXISTS t_order (
    id BIGINT NOT NULL COMMENT '主键(雪花ID)',
    order_no VARCHAR(64) NOT NULL COMMENT '订单号，幂等键',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    status TINYINT NOT NULL DEFAULT 10 COMMENT '10待支付 50已取消',
    total_amount INT NOT NULL COMMENT '订单总额(分)',
    receiver VARCHAR(32) NOT NULL COMMENT '收货人快照',
    phone VARCHAR(20) NOT NULL COMMENT '手机号快照',
    province VARCHAR(64) NOT NULL COMMENT '省快照',
    city VARCHAR(64) NOT NULL COMMENT '市快照',
    district VARCHAR(64) NOT NULL COMMENT '区快照',
    detail VARCHAR(255) NOT NULL COMMENT '详细地址快照',
    remark VARCHAR(255) DEFAULT NULL COMMENT '备注',
    deleted TINYINT NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_order_no (order_no),
    KEY idx_order_user (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单表';
```

### 3.2 订单明细表 t_order_item

```sql
CREATE TABLE IF NOT EXISTS t_order_item (
    id BIGINT NOT NULL,
    order_id BIGINT NOT NULL COMMENT '订单ID',
    product_id BIGINT NOT NULL COMMENT '商品ID',
    sku_id BIGINT NOT NULL COMMENT 'SKU ID',
    sku_name VARCHAR(128) NOT NULL COMMENT 'SKU名快照',
    image VARCHAR(255) DEFAULT NULL COMMENT '图片快照',
    price INT NOT NULL COMMENT '成交单价(分)',
    quantity INT NOT NULL COMMENT '数量',
    deleted TINYINT NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_order_item_order (order_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单明细表';
```

## 5. 下单时序

```text
前端 → order
  1. 校验参数、SKU 与库存充足（预校验）
  2. product.deduct(skuId, quantity)    # 原子扣减，失败即库存不足
  3. 本地事务：创建订单 + 明细
     若失败 → product.restore(skuId, quantity)  # 回补库存
  4. 返回订单号
```

## 6. 幂等设计

- 客户端提交订单时生成 `requestId`，order 以此作为幂等键。
- 下单前以 `requestId` 查询是否已存在订单，存在则直接返回原订单，不重复扣库存、不重复建单。
- 建议将 `requestId` 存入订单表或独立幂等表，并加唯一索引。

## 7. 状态机

```text
10 待支付 ──取消──▶ 50 已取消
```

> P0 只保留「待支付 → 已取消」；支付、发货等状态由 `payment` 与后续模块扩展。

## 8. 错误码扩展

| 错误码 | 含义 |
|---|---|
| 400 | 参数错误 |
| 404 | 订单不存在 / 商品或 SKU 不存在 |
| 409 | 库存不足 / 订单状态不允许该操作 |
| 403 | 无权操作该订单 |

## 9. 校验与安全

- 所有接口按 `X-User-Id` 隔离，订单归属校验在 Service 层完成。
- 数量 ≥ 1 且设置上限；金额由后端按快照计算，不信任前端传价。
