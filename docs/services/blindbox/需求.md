# 盲盒抽盒 需求文档

## 1. 背景与目标

盲盒是潮玩商城的核心玩法。本期目标：实现「系列 → 款式（含概率与隐藏款）→ 单抽」的完整抽盒链路，复用秒杀模块已打通的库存扣减能力，为后续「端盒」留出扩展空间。

## 2. 用户与场景

- 普通用户：浏览盲盒系列，单抽一次，查看自己抽中的款式。
- 运营/后台：维护盲盒系列与款式，配置每个款式的抽取概率与隐藏款。

## 3. 功能范围

### 本期 P0：单抽

| 编号 | 功能 | 说明 |
|---|---|---|
| BB-01 | 系列管理 | 系列增删改查（含价格、封面、状态） |
| BB-02 | 款式管理 | 系列下款式增删改，配置概率、隐藏款、关联 SKU |
| BB-03 | 单抽 | 按概率加权随机抽取款式，扣减对应 SKU 库存，生成抽盒记录 |
| BB-04 | 抽盒记录 | 查询自己的抽盒记录 |

### 后续 P1：端盒

- 整盒购买（6/12 个），一盒内款式不重复，剩余款式动态重算概率。

## 4. 功能详述

### BB-01 / BB-02 系列与款式

- 系列字段：名称、描述、封面、单价（分）、状态。
- 款式字段：款式名、图片、关联 SKU、抽取概率（万分比）、是否隐藏款。
- 同一系列所有款式的概率之和必须等于 10000，创建/修改时校验。

### BB-03 单抽

- 校验系列存在且启用。
- 按权重随机抽取一个款式，隐藏款概率极低。
- 抽中后原子扣减该款式对应 SKU 的库存。
- 库存不足时返回「该款式已售罄，请重试」，不生成记录。
- 抽盒记录保存：系列、款式、SKU、是否隐藏款、单价。

### BB-04 抽盒记录

- 按用户隔离，分页查询，按时间倒序。

## 5. 非功能需求

- 概率公平：加权随机算法，概率用万分比整数，避免浮点误差。
- 不超卖：抽中后扣库存复用 product 的原子扣减接口。
- 幂等：每次抽盒是一次独立随机事件，不做幂等；库存扣减原子性由 product 兜底。

## 6. 验收标准

- 能按配置概率抽中款式，库存正确扣减。
- 库存不足时返回明确错误，不生成记录。
- 概率之和不为 10000 的系列无法创建/修改。
- 用户只能看到自己的抽盒记录。
