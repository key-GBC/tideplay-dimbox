# 盲盒抽盒 技术设计

## 1. 概述

- 代码落于 `promotion` 模块，复用其 Redis / Feign 等已有依赖。
- 单抽扣库存复用 `product` 的原子扣减接口 `POST /product/stock/deduct`。
- 分层：`controller → service → mapper → entity/dto`。

## 4. 单抽时序

```text
用户 → gateway → promotion
  1. 校验系列存在且启用
  2. 查询系列全部款式
  3. 加权随机抽中一个款式
  4. product.deduct(skuId, 1)  # 原子扣库存，失败即售罄
  5. 写入 t_blindbox_order
  6. 返回抽中款式
```

## 5. 加权随机算法

- 概率用万分比整数，同一系列所有款式概率和 = 10000。
- 抽取：随机数 `r ∈ [1, 10000]`，按款式顺序累加概率，`r ≤ 累计值` 时命中该款式。

```java
int r = ThreadLocalRandom.current().nextInt(10000) + 1;
int acc = 0;
for (Item item : items) {
    acc += item.getProbability();
    if (r <= acc) return item;
}
```

## 6. 一致性与边界

- 库存扣减原子性：复用 `product.deduct` 的单条 SQL 条件更新，抽中但库存不足返回 409，不写记录。
- 概率校验：创建/修改系列时校验概率总和，避免配置错误。
- 后续端盒：一盒内不重复，需在抽取过程中排除已抽款式并动态重算剩余概率。

## 7. 错误码扩展

| 错误码 | 含义 |
|---|---|
| 404 | 系列/款式不存在 |
| 409 | 库存不足 / 概率总和不为 10000 |
