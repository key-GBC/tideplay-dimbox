# product 模块技术设计

## 1. 概述

- 沿用 Spring Boot 3.2 + MyBatis-Plus 3.5.7，复用 `common` 的 `Result`、错误码、异常、分页。
- 分层：`controller → service → mapper → entity/dto`。

## 2. 表结构

### 2.1 分类表 t_category

```sql
CREATE TABLE IF NOT EXISTS t_category (
    id BIGINT NOT NULL,
    parent_id BIGINT NOT NULL DEFAULT 0 COMMENT '父分类ID，0为顶级',
    name VARCHAR(64) NOT NULL COMMENT '分类名',
    icon VARCHAR(255) DEFAULT NULL COMMENT '图标',
    sort INT NOT NULL DEFAULT 0 COMMENT '排序',
    status TINYINT NOT NULL DEFAULT 1 COMMENT '状态:1启用 0禁用',
    deleted TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_category_parent (parent_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品分类表';
```

### 2.2 品牌表 t_brand

```sql
CREATE TABLE IF NOT EXISTS t_brand (
    id BIGINT NOT NULL,
    name VARCHAR(64) NOT NULL COMMENT '品牌名',
    logo VARCHAR(255) DEFAULT NULL COMMENT 'Logo',
    description VARCHAR(500) DEFAULT NULL COMMENT '描述',
    status TINYINT NOT NULL DEFAULT 1 COMMENT '状态:1启用 0禁用',
    deleted TINYINT NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id)

```

### 2.3 商品表 t_product

```sql
CREATE TABLE IF NOT EXISTS t_product (
    id BIGINT NOT NULL,
    category_id BIGINT NOT NULL COMMENT '分类ID',
    brand_id BIGINT DEFAULT NULL COMMENT '品牌ID',
    name VARCHAR(128) NOT NULL COMMENT '商品名',
    sub_title VARCHAR(255) DEFAULT NULL COMMENT '副标题',
    main_image VARCHAR(255) DEFAULT NULL COMMENT '主图',
    detail TEXT COMMENT '详情',
    status TINYINT NOT NULL DEFAULT 0 COMMENT '状态:1上架 0下架',
    deleted TINYINT NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_product_category (category_id),
    KEY idx_product_brand (brand_id)

```

### 2.4 SKU 表 t_product_sku

```sql
CREATE TABLE IF NOT EXISTS t_product_sku (
    id BIGINT NOT NULL,
    product_id BIGINT NOT NULL COMMENT '商品ID',
    sku_name VARCHAR(128) NOT NULL COMMENT '规格/款式名',
    image VARCHAR(255) DEFAULT NULL COMMENT 'SKU图片',
    price INT NOT NULL COMMENT '价格(分)',
    stock INT NOT NULL DEFAULT 0 COMMENT '库存',
    status TINYINT NOT NULL DEFAULT 1 COMMENT '状态:1启用 0禁用',
    deleted TINYINT NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_sku_product (product_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品SKU表';
```

## 4. 关键流程

- 商品创建：校验分类/品牌存在 → 插入 SPU → 批量插入 SKU（至少 1 个），事务保证。
- 分类树构建：查询全部启用分类 → 内存按 `parent_id` 组装成树。
- 库存扣减原子性：用一条 SQL 完成，`UPDATE t_product_sku SET stock = stock - ? WHERE id = ? AND stock >= ?`，受影响行数为 0 判定库存不足。
- 上下架：更新 `status`，用户端查询强制 `status = 1`。

## 5. 并发与防超卖设计

### 5.1 目标与分层

短时间内大量用户下单同一商品时，防超卖需要分层设计。本期只落地「数据库层」，缓存/削峰/限流留给后续秒杀模块。

| 层级 | 手段 | 本期(P0) | 秒杀模块 |
|---|---|---|---|
| 数据库层 | 原子条件扣减，保证正确性 | ✅ | 保留为最后防线 |
| 缓存层 | 库存预热 Redis，Lua 原子扣减 | - | ✅ |
| 削峰层 | Redis 扣减成功后发 MQ 异步落库 | - | ✅ |
| 流量层 | 网关限流 + 用户限购 + 幂等 | - | ✅ |

### 5.2 本期：数据库原子扣减

```sql
UPDATE t_product_sku
SET stock = stock - #{quantity}
WHERE id = #{skuId} AND stock >= #{quantity}
```

- InnoDB 对同一行加行锁，并发 UPDATE 串行执行，扣减天然原子。
- `stock >= quantity` 条件保证扣减后不为负。
- 用受影响行数判断：返回 0 即库存不足，返回 409，不创建订单。
- 实现上建议用 `ProductSkuMapper` 的 `@Update` 自定义 SQL，保证一条语句完成。

### 5.3 后续：Redis 预扣 + MQ 削峰（秒杀模块）

秒杀等高并发场景，直接打 DB 会让行锁成为瓶颈。届时引入：

1. 库存预热到 Redis，用 Lua 脚本原子扣减：

```lua
local stock = tonumber(redis.call('get', KEYS[1]))
local qty = tonumber(ARGV[1])
if stock and stock >= qty then
  redis.call('decrby', KEYS[1], qty)
  return 1
end
return 0
```

2. MQ 削峰：Redis 扣减成功后发送消息到 RabbitMQ，异步落库完成最终扣减。
3. 限流防刷：网关 Sentinel 限流 + 用户维度限购 + 请求幂等。

### 5.4 一致性配套

- 幂等：同一订单只扣一次库存。
- 库存回补：下单超时取消、支付失败时回补库存。
- 最终一致：Redis 扣减与 DB 落库之间用消息队列 + 失败重试/补偿对账。

> 本期只实现 5.2；5.3 / 5.4 在秒杀与订单模块中落地。

## 6. 错误码扩展

| 错误码 | 含义 |
|---|---|
| 404 | 分类/品牌/商品/SKU 不存在 |
| 409 | 分类下存在子分类 / 库存不足 |

## 7. 校验与安全

- 价格、库存非负；商品创建时 SKU 至少 1 个。
- 后台管理接口需登录；角色隔离后续接入网关后收紧。
