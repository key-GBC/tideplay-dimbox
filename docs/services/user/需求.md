# user 模块需求文档

## 1. 背景与目标

`user` 服务已具备注册、登录、JWT 签发与「当前用户」查询能力。本期目标：补齐个人中心的基础能力，并为后续 `order` 下单链路提供「收货地址」这一前置依赖。

## 2. 用户与场景

- 已登录用户：维护个人资料、修改密码、管理收货地址。
- 未登录用户：本期接口均需登录，未登录由网关统一拦截。

## 3. 功能范围

### 本期 P0

| 编号 | 功能 | 说明 |
|---|---|---|
| U-01 | 查询资料 | 查看昵称、头像、性别、生日、简介、手机、邮箱 |
| U-02 | 修改资料 | 修改昵称、头像、性别、生日、简介 |
| U-03 | 修改密码 | 校验旧密码，更新新密码 |
| U-04 | 收货地址 | 新增、列表、修改、删除、设置默认 |

### 后续（不在本期）

- 手机号 / 邮箱绑定（验证码）、头像上传（对象存储）、实名认证、账号注销。

## 4. 功能详述

### U-01 查询资料

- 返回字段：`id`、`username`、`nickname`、`avatar`、`gender`、`birthday`、`bio`、`phone`、`email`。
- 不返回 `password`、`deleted`、`status` 等敏感或内部字段。

### U-02 修改资料

- 可修改字段：`nickname`、`avatar`、`gender`、`birthday`、`bio`。
- `username` 不可改；`phone`、`email` 涉及验证码，放后续。
- 校验：`nickname` 最长 32 字；`bio` 最长 255 字；`gender` 取值 0/1/2；`birthday` 格式 `yyyy-MM-dd` 且不晚于当天。
- 空值语义：`avatar`、`birthday`、`bio` 允许清空。

### U-03 修改密码

- 请求：`oldPassword`、`newPassword`。
- 规则：`newPassword` 6-20 位；`newPassword` 不得与 `oldPassword` 相同；`oldPassword` 必须正确。
- 成功后要求重新登录（前端清除本地 token 并跳转登录页）。

### U-04 收货地址

- 字段：`receiver`、`phone`、`province`、`city`、`district`、`detail`、`is_default`。
- 规则：
  - 每个用户最多 20 个地址，超出拒绝新增。
  - 默认地址最多 1 个；设置新默认时自动取消原默认。
  - `receiver` 1-32 字；`phone` 为 11 位大陆手机号；`detail` 1-255 字。
  - 删除为逻辑删除；删除默认地址后，若仍存在其他地址，则自动把最新一条设为默认。
  - 用户只能操作自己的地址（按 `X-User-Id` 隔离）。

## 5. 非功能需求

- 鉴权：所有接口经网关，token 缺失或过期返回 `401`。
- 一致性：默认地址唯一性在事务内保证。
- 安全：密码 BCrypt 存储，任何接口不返回密码。

## 6. 验收标准

- 未登录访问任一接口返回 `401`。
- 能正常查询、修改资料，且校验规则生效。
- 改密码后旧密码无法登录，新密码可登录。
- 地址增删改查正常，任意时刻默认地址 ≤ 1，且总数 ≤ 20。
