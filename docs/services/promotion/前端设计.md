# promotion 前端设计（用户端秒杀板块）

## 1. 概述

- 技术栈与 `web` 其他页面一致：Vue3 + Element Plus + Pinia + Vue Router + Axios。
- 目标：补齐用户端秒杀板块，复用 promotion 已有的「活动列表 / 抢购 / 我的记录」三个接口。
- 盲盒板块前端已实现，本文档只覆盖秒杀板块。

## 2. 页面与路由

| 路由 | 页面 | 说明 |
|---|---|---|
| /seckill | SeckillList | 秒杀活动列表 + 抢购按钮 |
| /seckill/record | SeckillRecord | 我的秒杀记录 |

入口：首页顶栏新增「秒杀」按钮跳转 `/seckill`。

## 3. API 封装

新建 `api/seckill.js`：

| 函数 | 后端接口 |
|---|---|
| getSeckillActivityList(params) | GET /api/promotion/seckill/activity |
| buySeckill(activityId) | POST /api/promotion/seckill/{activityId}/buy |
| getSeckillRecord(params) | GET /api/promotion/seckill/record |

## 4. 数据字段

### 活动列表项 SeckillActivityResponseDto

`id`、`skuId`（字符串）、`seckillPrice`（分）、`stock`、`startTime`、`endTime`、`status`。

### 秒杀记录项 SeckillOrderResponseDto

`id`、`activityId`、`skuId`、`orderNo`、`status`（0 待扣库存 / 1 已扣库存）、`createAt`。

## 5. 关键交互

### 活动状态判断（前端按时间）

```text
now < startTime       未开始，按钮禁用显示「未开始」
startTime ≤ now ≤ endTime  进行中，按钮可点「立即抢购」
now > endTime         已结束，按钮禁用显示「已结束」
```

后端 `buy` 会再次校验时间，前端判断仅用于按钮状态展示。

### 抢购

- 点击「立即抢购」调用 `buySeckill(activityId)`。
- 成功返回 `orderNo`，提示「抢购成功」，抢购是异步落库，可引导用户稍后到记录页查看。
- 失败（已抢购 / 库存不足 / 未开始或已结束）由 request 拦截器统一弹出后端 message。

### 倒计时 / 状态刷新

- 活动卡片用 `setInterval` 每秒刷新一次本地状态，用于按钮从「未开始」自动切到「进行中」。
- 组件卸载时清理定时器。

## 6. 已知限制

- 活动列表与记录只返回 `skuId`，不含 SKU 名称与图片，前端以 `skuId` 展示占位；后续可在 promotion 活动列表接口里补充 SKU 信息。
