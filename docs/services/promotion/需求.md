# promotion 模块需求文档

## 1. 背景与目标

`promotion` 是潮玩商城的差异化核心。本期目标：落地之前 product 设计预留的防超卖三层方案（Redis 预扣 + MQ 削峰 + 限流），实现一个完整、可并发压测的「秒杀」闭环；盲盒抽盒作为后续迭代。

## 2. 用户与场景

- 普通用户：在秒杀时间段抢购限量商品，限购一件。
- 运营/后台：创建秒杀活动，设定商品、秒杀价、限量库存与起止时间。
- 高并发：大量用户同时抢同一商品，不能超卖、不能重复下单。

## 3. 功能范围

### 本期 P0：秒杀

| 编号 | 功能 | 说明 |
|---|---|---|
| PRO-01 | 秒杀活动管理 | 创建/查询活动，设定 SKU、秒杀价、库存、起止时间 |
| PRO-02 | 库存预热 | 活动开始前把秒杀库存写入 Redis |
| PRO-03 | 秒杀抢购 | Lua 原子扣减 + 用户限购 + 幂等 |
| PRO-04 | 异步落库 | 抢购成功发 MQ，消费者扣 DB 库存并生成秒杀记录 |
| PRO-05 | 限流 | 网关 Sentinel 对抢购接口限流 |

### 后续 P1：盲盒抽盒

- 系列/款式概率配置、抽取款式、端盒、隐藏款，复用秒杀的库存与一致性基础设施。

## 4. 功能详述

### PRO-01 / PRO-02 活动与预热

- 活动字段：SKU、秒杀价（分）、秒杀库存、开始/结束时间。
- 秒杀库存独立于商品库存（秒杀期间以秒杀价、秒杀库存为准）。
- 创建活动或活动开始时，把秒杀库存预热到 Redis。

### PRO-03 抢购

- 校验：活动处于进行中。
- 限购：同一用户同一活动只能抢一次。
- 扣减：Redis Lua 脚本原子完成「校验限购 + 扣库存 + 记录用户」，任一步不满足即失败。
- 返回：抢购成功返回「排队中」，不阻塞等待落库。

### PRO-04 异步落库

- 抢购成功发 RabbitMQ 消息，消费者幂等处理：扣减 DB 库存 + 写入秒杀订单记录。
- 消费失败重试，最终一致。

## 5. 非功能需求

- 防超卖：Redis 扣减为第一道闸，DB 条件扣减为最后防线。
- 幂等：抢购与消费均幂等，同一用户同一活动只产生一条记录。
- 最终一致：Redis 与 DB 之间用 MQ 保证，失败可重试。

## 6. 验收标准

- 并发抢购库存不超卖，抢到人数 ≤ 秒杀库存。
- 同一用户重复抢购只成功一次。
- 活动未开始或已结束不可抢购。
- 抢购成功后，异步落库完成，可查询到秒杀记录。
