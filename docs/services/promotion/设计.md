# promotion 模块技术设计

## 1. 概述

- 沿用 Spring Boot 3.2 + MyBatis-Plus 3.5.7，复用 `common`。
- 新增基础设施：Redis（预扣）、RabbitMQ（削峰）、Sentinel（限流）。
- 分层：`controller → service → mapper → entity/dto`，异步链路走 MQ。

## 2. 新依赖接入

| 依赖 | 用途 | 接入位置 |
|---|---|---|
| spring-boot-starter-data-redis | 库存预热 / Lua 扣减 / 限购 | promotion |
| spring-boot-starter-amqp | 抢购成功消息异步落库 | promotion |
| spring-cloud-starter-alibaba-sentinel | 抢购接口限流 | gateway + promotion |

> 版本分别由 Spring Boot 与 Spring Cloud Alibaba 管理，无需额外指定版本。

## 3. 表结构

### 3.1 秒杀活动表 t_seckill_activity

```sql
CREATE TABLE IF NOT EXISTS t_seckill_activity (
    id BIGINT NOT NULL COMMENT '主键(雪花ID)',
    sku_id BIGINT NOT NULL COMMENT '秒杀SKU',
    seckill_price INT NOT NULL COMMENT '秒杀价(分)',
    stock INT NOT NULL COMMENT '秒杀库存',
    start_time DATETIME NOT NULL COMMENT '开始时间',
    end_time DATETIME NOT NULL COMMENT '结束时间',
    status TINYINT NOT NULL DEFAULT 1 COMMENT '1启用 0禁用',
    deleted TINYINT NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_seckill_time (start_time, end_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='秒杀活动表';
```

### 3.2 秒杀订单记录表 t_seckill_order

```sql
CREATE TABLE IF NOT EXISTS t_seckill_order (
    id BIGINT NOT NULL,
    activity_id BIGINT NOT NULL COMMENT '活动ID',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    sku_id BIGINT NOT NULL COMMENT 'SKU ID',
    order_no VARCHAR(64) NOT NULL COMMENT '订单号',
    status TINYINT NOT NULL DEFAULT 1 COMMENT '1已抢到 2已取消',
    deleted TINYINT NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_seckill_user (activity_id, user_id),
    KEY idx_seckill_order_user (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='秒杀订单记录表';
```

> `uk_seckill_user` 保证同一用户同一活动只有一条记录，是消费幂等的最后防线。

## 4. Redis 数据结构

| Key | 类型 | 说明 |
|---|---|---|
| `seckill:stock:{activityId}` | string | 秒杀库存，预热时写入 |
| `seckill:users:{activityId}` | set | 已抢购用户集合（限购） |

## 5. Lua 原子扣减

```lua
-- KEYS[1]=库存key KEYS[2]=用户集合key ARGV[1]=userId ARGV[2]=数量
if redis.call('sismember', KEYS[2], ARGV[1]) == 1 then
  return -1
end
local stock = tonumber(redis.call('get', KEYS[1]) or '0')
if stock < tonumber(ARGV[2]) then
  return 0
end
redis.call('decrby', KEYS[1], ARGV[2])
redis.call('sadd', KEYS[2], ARGV[1])
return 1
```

> 限购检查、库存校验、扣减、记录用户在单条 Lua 内完成，Redis 单线程保证原子。

## 6. 秒杀时序

```text
用户 → gateway(Sentinel 限流) → promotion
  1. 校验活动时间
  2. Lua 原子扣减（限购 + 库存）
  3. 成功后发 MQ 消息
  4. 立即返回「抢购成功，处理中」

MQ 消费者（promotion）
  1. 幂等校验（唯一索引兜底）
  2. product.deduct 扣 DB 库存
  3. 写入 t_seckill_order
```

## 7. 幂等与最终一致

- 抢购幂等：Redis `sismember` 已抢直接拒绝。
- 消费幂等：`uk_seckill_user` 唯一索引，重复消息直接丢弃。
- 最终一致：Redis 扣减成功但 DB 落库失败时，消息重试；死信队列兜底。

## 9. 错误码扩展

| 错误码 | 含义 |
|---|---|
| 404 | 活动不存在 |
| 409 | 已抢购 / 库存不足 / 活动未开始或已结束 |
| 429 | 请求过于频繁（Sentinel 限流） |
